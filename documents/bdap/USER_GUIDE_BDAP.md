## 1. Что такое БД АП

🏷 **Темы:** назначение БДАП, база данных агрегированных показателей, что такое БДАП

**БД АП (База данных агрегированных показателей)** — информационная система для хранения и управления агрегированными статистическими данными, загружаемыми через файлы форматов DBF и Excel.

**Ключевые принципы:**
- Загруженные пакеты **не утверждаются автоматически** — они попадают в статус «Регистрация»
- Утверждение требует явного действия уполномоченного пользователя
- Все действия с пакетом фиксируются в истории

## 2. Процесс загрузки данных

🏷 **Темы:** как загрузить данные, загрузка пакета, модуль загрузки, DBF, Excel, загрузчик

### Шаг 1. Открыть модуль загрузки
Перейдите в раздел «Загрузка данных» в системе БД АП.

> Требуется роль: `EStatBDAP_VIEW`

### Шаг 2. Загрузить файл
- Выберите файл формата DBF или Excel (.xls, .xlsx)
- Система проверяет: формат файла, наличие обязательных колонок, дубликаты, корректность значений

### Шаг 3. Автоматическая обработка
После загрузки система проходит через статусы 010 → 015 → 020 → 035 → 040 → 055 → 060 → 075 → 080 → 100 → **101 (Регистрация)**

Если обнаружены ошибки → пакет получает статус «Ошибка при загрузке» с описанием проблемы.

### Шаг 4. Просмотр загруженных данных
Пользователи могут просматривать содержимое пакета. Пакет в статусе «Регистрация» можно удалить если данные некорректны.

## 3. Процесс утверждения пакетов

🏷 **Темы:** как утвердить пакет, утверждение данных, кто может утверждать, роль утверждающего

> Требуются роли: `EStatBDAP_AGREEMENT` + `EstatSectorXX` (соответствующей отрасли)

### Шаг 1. Открыть пакет
Утверждающий открывает пакет в статусе «Регистрация» и просматривает содержимое.

### Шаг 2. Проверка данных
Проверить: корректность данных, соответствие бизнес-правилам, наличие всех необходимых показателей.

### Шаг 3. Принять решение

**Если данные корректны:**
- Нажать «Утвердить» → пакет получает статус **102 (Утверждён)**
- Утверждённые данные публикуются в ИАС Талдау

**Если данные содержат ошибки:**
- Нажать «Отправить на доработку» → указать причину
- Пакет получает статус **104 (Отправлен на доработку)**
- Данные автоматически удаляются из БД

## 4. Работа с ДБФ файлами

🏷 **Темы:** ДБФ файлы, вкладка ДБФ файлы, список пакетов, пары, соответствие полей

### Вкладка «ДБФ файлы»

Используется для добавления наименований файлов в базу данных и привязки к формам.

**Кнопки управления:**
- **Добавить** — добавление нового ДБФ файла
- **Изменить** — редактирование записи
- **Удалить** — удаление ДБФ файла
- **Фильтр** — поиск пользователям ДБФ файлов
- **Обновить** — обновление окна

### Вкладка «Список пакетов»
🏷 **Темы:** список пакетов, просмотр пакетов, история загрузок

Отображает все загруженные пакеты данных в табличном виде с полями:
- Имя файла
- Дата и время загрузки
- Пользователь, выполнивший загрузку
- Текущий статус пакета
- История изменений статусов

### Вкладка «Пары»
🏷 **Темы:** пары, связь файлов, привязка файлов к формам

Используется для настройки связей между файлами и статистическими формами.

### Вкладка «Соответствие полей к акронимам»
🏷 **Темы:** соответствие полей, акронимы, маппинг полей

Настройка соответствия полей загружаемых файлов к акронимам системы.

## 5. Создание Excel файлов для загрузки

🏷 **Темы:** создание Excel файла, как создать файл для загрузки, формат файла, шаблон

### Требования к файлу
- Формат: .xls или .xlsx
- Кодировка: соответствующая системным требованиям
- Обязательные колонки должны присутствовать

### Порядок создания
1. Скачать актуальный шаблон из системы
2. Заполнить данные в соответствии с форматом
3. Не изменять структуру столбцов
4. Сохранить файл
5. Загрузить через модуль «Загрузка данных»

## 6. Типичные ошибки и их решение

🏷 **Темы:** ошибки загрузки, проблемы с пакетом, что делать если ошибка

### Пакет получил статус «Ошибка при загрузке»
**Причина:** некорректный формат файла, отсутствие обязательных колонок, дубликаты, некорректные значения.
**Решение:** Проверить протокол загрузки, исправить файл и загрузить повторно.

### Пакет завис в статусе «Регистрация»
**Причина:** нет утверждающего пользователя или утверждающий не выполнил действие.
**Решение:** Обратиться к пользователю с ролью `EStatBDAP_AGREEMENT` для утверждения.

### Нет доступа к модулю загрузки
**Причина:** отсутствует роль `EStatBDAP_VIEW`.
**Решение:** Обратиться к администратору системы для назначения роли.

### Нет кнопки «Утвердить»
**Причина:** отсутствует роль `EStatBDAP_AGREEMENT` или `EstatSectorXX`.
**Решение:** Обратиться к администратору для назначения нужных ролей.


## 7.Как подготовить данные к загрузке БД АП ?

Структура создания xls - файлов для загрузки в БД АП.

Формат файла MSExcel
1.	Наименование файла MSExcel необходимо прописать в следующем порядке:
1)	первые 2 символа цифры отрасли по КСП;
2)	далее 3 символа - буквы на РУССКОМ ЯЗЫКЕ (по усмотрению сотрудников отраслевых департаментов, они могут означать наименование отрасли, показателя или управления, по удобству);
3)	далее необходимо указать периодичность данных через нижнее подчеркивание.
      Например:
-	месячные за любой год: 14ВАЛ_М, 14ИНД_М
-	месячные с накоплением за любой год: 14ВАЛ_М_ПЕРИОД, 14ИНД_М_ПЕРИОД
-	квартальные за любой год: 14ВАЛ_КВ, 14ИНД_КВ
-	квартальные с накоплением за любой год: 14ВАЛ_КВ_ПЕРИОД, 14ИНД_КВ_ПЕРИОД
-	полугодовые за любой год: 14ВАЛ_ПГ,14ИНД_ПГ
-	годовые: 14ВАЛ_Г, 14ИНД_Г
4)	далее в название файла необходимо указать STDA, один файл = один STDA,то есть если файлы подаются, к примеру, за март 2014 года то в имени файла необходимо добавить STDA:
-	14ВАЛ_М02, 14ВАЛ_М03, 14ВАЛ_М05, 14ВАЛ_М24, 14ВАЛ_М26 и так далее, где в имени файла 02, 03, 05, 24, 26 представляют собой тип данных STDA.Данный принцип справедлив для всех типов периодов: 14ВАЛ_М03, 14ВАЛ_М_ПЕРИОД03, 14ВАЛ_КВ03, 14ВАЛ_КВ_ПЕРИОД03 и так далее.
2.	Файл должен содержать данные только по одному отчетному периоду и по одному STDA.
3.	При описании показателя в разных разрезностях (по разным справочникам и классификаторам) в ячейках по не используемым справочникам и классификаторам ничего не проставляется, т.е. пустая ячейка.
4.	В файле первая строка должна содержать наименования столбцов на английском языке (перечень аббревиатур классификаторов и справочников на английском языке прилагается).
5.	Столбцы KCP, MKEI, MKEIKPC, SKFD, STDA, PERIOD, DATA, должны быть первые в таблице (и идти в том же порядке), а за ними идти все имеющиеся разрезности, наименование столбцов которых должно соответствовать аббревиатурам справочников и классификаторов, далее проставляется POK.
6.	Все столбцы (кромеDATAPOK) должны быть текстовые (символьные).
7.	Поле DATA должно быть в формате Краткий формат Даты, поле POK должно быть в формате Числовой
8.	Текстовые поля не должны содержать пробелов перед кодом и между знаками.
9.	Строки в таблице должны быть уникальными по следующему набору столбцов: KCP, MKEI, MKEIKPC, SPPD, STDA, PERIOD, POK и всех его разрезностей.
10.	В столбце MKEI должно быть значение кода единицы измерения по данному показателю.
11.	В столбце MKEIKPC может быть значение кода единицы измерения для данного факта, если единица измерения зависит от значения одной из ее разрезности (справочника или классификатора).
12.	В ячейках значения по классификаторам и справочникам должны соответствовать ИС КЛАССу.
       Все данные предоставляются по текущей версии справочников.
       Если Вы предоставляете не пересчитанные данные по закрытым кодам, то имя поля в Excel файлах должно содержать «год», в котором эти элементы действовали (например:ОКЭД2003).
       Если же Вы предоставляете пересчитанные данные по действующим (открытые) элементам справочника, то имя поля в Excel файлах не должно содержать  «год» (например: ОКЭД).
